# Verification of generators and metrics

Every generator and metric the pipeline runs, checked against its paper or upstream reference implementation. Each row ends in one of four states:

- **Verified**: matches the reference, by code reading or a test against an independent computation.
- **Fixed**: our code or fork had a bug against the reference; the fix and a regression test are in the repo.
- **Deviation**: differs from the reference on purpose; the reason is given.
- **Open**: a known upstream problem we have not fixed; the impact on results is stated so you can judge how much to trust the number.

IDs such as SC-05 or SE-12 refer to the evaluation audit of 2026-10-07, KA-01 to KA-07 to the known-answer checks of 2026-10-09, and N1 to N9 to the re-audit of 2026-10-10. Reference tests live in `tests/unit/test_synthcity_reference_metrics.py`, `tests/unit/test_syntheval_reference_metrics.py` and `tests/unit/test_log_disparity_metrics.py`; the end-to-end ordering checks ("copy of train" vs "column shuffle") are in `tests/integration/test_metric_known_answers.py`. Two checks keep this table true over time: every evaluation run tests that the two baselines land where they must on the real data (`checks.csv`, [user manual](user-manual.md#output-checks)), and the opt-in golden test (`pytest tests/integration -m regression`) flags any metric whose value on the fixture moves after a dependency or submodule bump.

## Data readiness

`synthdata/data_readiness.py` checks the train split at the start of `synthdata-impute`, before any model is fitted, and writes `data_readiness.csv` (check, column, value, threshold, status, suggested action) to the imputation output folder, a grouped log line per check, and a summary table in report.md section 6. It only advises: no column is dropped or changed. Every threshold is in `data.readiness` and can be set to null to turn its check off. Checking the data before fitting follows Breck et al., "The ML Test Score" (IEEE Big Data 2017, data tests) and TensorFlow Data Validation (Caveness et al., SIGMOD 2020). Only the train split decides; the tuning and test splits are compared with it only to find levels a generator cannot produce and groups too small to score.

| Check | Default rule | Source and reason |
|---|---|---|
| `constant` | one distinct value in train | Zero variance, as in caret's `nearZeroVar` and scikit-learn's `VarianceThreshold(0)`. It carries no information and makes covariance-based metrics singular. |
| `near_zero_variance` | most common value more than 19x (95/5) the second, and at most 10% distinct values | caret `nearZeroVar` defaults `freqCut = 95/5`, `uniqueCut = 10` (Kuhn, J. Stat. Softw. 2008; Kuhn & Johnson, *Applied Predictive Modeling*, 2013, §3.5). Such columns can become constant within a split. |
| `duplicate` | categorical columns that split the rows the same way (identical up to relabelling); other columns with identical values | Perfect collinearity makes a covariance matrix singular. This is the cause of the DomiasMIA_prior failure on LORIS (`scipy.stats.gaussian_kde`: "data appears to lie in a lower-dimensional subspace"). Duplicates also double-weight one signal in distance metrics (DCR, NNDR, identifiability). |
| `high_correlation` | abs(Spearman) >= 0.95 between continuous columns (Pearson on ranks, pairwise-complete) | caret `findCorrelation` (default cutoff 0.90; Kuhn & Johnson §3.5). The stricter 0.95 is our choice, so only near-redundant pairs are flagged, such as an item and a total that is mostly that item. |
| `heavy_missingness` | >= 50% missing in train (warn); columns already kept as indicator-only are listed as info | There is no universal cutoff. Jakobsen et al. (BMC Med. Res. Methodol. 2017) treat results as hypothesis-generating beyond about 40% missing on important variables, and Madley-Dowd et al. (J. Clin. Epidemiol. 2019) show that the share alone should not decide whether to impute. So this is advice: above half, most of a column's values are the imputer's, not data. |
| `rare_categories` | levels with < 5 train rows | The "expected count of at least 5" rule (Cochran, Biometrics 1954), the same floor the HPO coverage screens use (`synthdata.generation.hpo.protected_scores`). A minimum cell size of about 5 is also common in disclosure control, since rare categories are the easiest to re-identify. |
| `high_cardinality` | nominal column with > 50 levels | Each level is a separate one-hot input and a separate conditional in CTGAN's training-by-sampling (Xu et al., NeurIPS 2019). Micci-Barreca (SIGKDD Explor. 2001) describes the problem. The 50 is our choice. |
| `unseen_category` | a level in tuning (or test) that search-train (or train) lacks | A generator samples only categories it was trained on, and one-hot encoders must be told how to handle unknown levels (scikit-learn `OneHotEncoder(handle_unknown=...)`). |
| `split_constant` (info) | constant in tuning or test but not in train | Metrics fitted on that split see a constant column. |
| `skewed` (info) | abs(skewness) > 2 | West, Finch & Curran (1995, in Hoyle, *Structural Equation Modeling*): skew above 2 is substantial non-normality. Gaussian-based normalisation in the generators fits the tail poorly. |
| `zero_inflated` (info) | >= 50% exact zeros in a continuous column | A point mass that mode-specific normalisation (CTGAN/TVAE) models as one narrow mode. The 50% is our choice. |
| `identifier_like` | identifier-like name, or a categorical/text column unique on >= 90% of rows | HIPAA Safe Harbor direct identifiers (45 CFR 164.514(b)(2)); same rule as the existing load-time warning. |
| `rows_per_column` | < 10 train rows per modelled column | Borrowed from the 10-events-per-variable rule of predictive modelling (Peduzzi et al., J. Clin. Epidemiol. 1996; see Riley et al., BMJ 2020, for its limits). There is no established rule for generators; it flags data like LORIS (about 2.6 rows per column), where deep generators underfit. |
| `small_group` | a target class or categorical protected group with < 5 rows in tuning or test | The same 5-row floor. Per-class TSTR and per-group fairness metrics, and the HPO protected-group screens, are unstable below it. |

## Imputation

| Method | Reference | Status | Notes |
| --- | --- | --- | --- |
| miceforest (default) | van Buuren, *Flexible Imputation of Missing Data* 2018 (MICE, predictive mean matching); `miceforest` 6 (LightGBM) | Library | The library's own defaults (48-tree LightGBM random forests, 5 mean-match candidates, "normal" matching), 5 rounds and one imputed dataset. Ours: nominal columns are classification targets; ordinal codes and continuous columns are regression targets matched to observed donors, so ordinal fills keep their order and are always observed codes. The kernel is fitted on the fit rows and only applied to other rows (`impute_new_data`), with donors from the fit rows. Columns with a single observed category are filled with it and not modelled. Unit tests check that fills are observed values, that minority classes and spread survive where MissForest collapses them, and that fits and transforms repeat for a seed. Made the default on 2026-10-22 after the simulated data showed MissForest filling categorical columns with one class and continuous ones with a narrow spike; this changes imputed values, so results are not comparable with earlier runs. miceforest 6.0.5 calls a private LightGBM method that changed in 4.7, so LightGBM is capped below 4.7. |
| missforest | Stekhoven & Buehlmann, *Bioinformatics* 2012; scikit-learn `IterativeImputer` + `RandomForestRegressor` | Deviation | scikit-learn's documented MissForest equivalent. Differences from the R package: nominal columns with more than two categories are one-hot encoded and the most likely category is kept (MissForest uses classification forests), binary and ordinal columns are imputed as codes and rounded, and the defaults are 50 trees and 5 rounds instead of 100 and 10. hyperimpute's `missforest` plugin was not used: it refits on whatever it transforms, so it cannot fit on train and fill the holdout. |
| simple | scikit-learn `SimpleImputer` (median / most frequent) | Verified | Unit test checks the fill equals the fit rows' median and mode and that transformed rows do not move it. Used by CI. |
| two-phase fit | refit after selection, as scikit-learn `GridSearchCV(refit=True)` | Verified | HPO fits and scores on data imputed by an imputer fitted on train minus tuning; the final models and the holdout use one refitted on all of train with the same settings and seed. `imputation_drift.csv` reports how much the two fits disagree on the cells both fill (Wasserstein / std for continuous, total variation for categorical). |
| missing indicators and re-masking | Sperrin et al., *Stat Med* 2020; scikit-learn `MissingIndicator` | Verified | Indicators are computed from the raw values for columns missing in at least 5% of the train rows outside tuning. Evaluation scores the filled data with indicators, because SynthEval and synthcity metrics need complete data; the indicators make the missingness pattern part of what fidelity metrics compare. `released/<model>.csv` has values blanked where the synthetic indicator is 1. |
| missing blocks and block flags | Jaccard similarity of missing masks with average-linkage clustering (`scipy`); depth-2 `sklearn` decision tree, 5-fold ROC AUC | Custom (advisory) | No library labels missingness patterns, so this is a small descriptive report: blocks group columns whose missing rows overlap by at least 0.9 on average; a pattern is a skip-logic candidate when the tree on other columns reaches AUC 0.95 (predictors exclude the target and any column blank in more than 10% of the pattern's missing rows, so co-missing forms do not count as rules; indicator-only columns are never put in blocks), a form-not-given candidate when a block is missing as a whole in at least 80% of its missing rows. Labels are candidates for review, never applied automatically. Block flags (`missing_indicators.blocks`) are 1 where the whole block is missing; column flags then cover only the remaining gaps, so generators see one flag per form rather than several identical ones. ### Why macro AUPRC rather than macro-F1 (2026-10-20)

The simulated and LORIS configs fix `hpo.objective: tstr_macro_auprc` for every model. Evidence is the study database of the sim run 1.4_full (9,000-row sample; 7 models, 189 completed trials):

- **One objective for all models.** `objective: auto` chose macro-F1 for CTGAN and ARF, AUROC for TVAE and RTVAE and AUPRC for the rest. The holdout ranking stays fair, but the HPO gains of different models measured different things and could not be compared.
- **F1 depends on a decision rule; AUPRC does not.** Macro-F1 scores the argmax prediction, so it changes only when a row's predicted class flips, and a candidate whose classifier predicts nearly one class gets a very low F1 whatever its probabilities say. In this run such degenerate candidates (F1 0.04 to 0.13 for PATE-GAN and ADS-GAN trials whose AUPRC was 0.333 to 0.343, about chance) produced most of F1's spread across trials for the GAN models. AUPRC ranks the predicted probabilities, so it rewards a candidate that keeps the relation between features and target even when the argmax is off. It is also prevalence-aware: chance is the class prevalence, unlike AUROC, whose chance is 0.5 for every class.
- **Seed noise is larger for F1.** Refitting the top trials with new seeds moved CTGAN's macro-F1 by an SD of 0.0145, against a bootstrap SE of 0.0107 (ARF 0.0092 against 0.0094). Trials were selected on the bootstrap SE alone, so a one-SE F1 gain is mostly seed noise: CTGAN's best single F1 (0.361) refitted to a mean of 0.338. For AUPRC the seed SD was about equal to the bootstrap SE (ADS-GAN 0.0068 against 0.0058).
- **Where the generators keep the label relation, the two agree.** TVAE and RTVAE are the only models whose trials vary well beyond noise (reliability 0.77 and 0.79 on AUPRC), and there F1 and AUPRC rank trials alike (Spearman 0.88 and 0.74). Across all trials the agreement is 0.45, so the choice matters mainly for models near chance, where F1 rewards a lucky threshold.
- **Headroom.** The real-data ceiling on the tuning rows is AUPRC 0.400 against chance 0.333 (6.7 bootstrap SEs), and macro-F1 0.399 (7.3 SEs). Both have room, so headroom does not decide between them.
- **Evaluation.** Macro AUPRC is one of the three ranked holdout TSTR scores, with macro-F1 and balanced accuracy. Every trial still logs macro-F1, AUROC, kappa and balanced accuracy, so `scripts/hpo_analysis.py compare` shows which trial F1 would have chosen.

The trade-off: macro-F1 is the score most readers know, and it is the one a deployed classifier with a fixed decision rule would face. A model tuned on AUPRC can score lower on F1 than one tuned on F1; the holdout report shows both.

## Column types

Every discrete/continuous decision follows the variable schema: categorical columns (nominal, ordinal, missing indicators, and the target when categorical) are discrete, all others continuous. Without this, synthcity guesses from the number of distinct values: its encoders (CTGAN, TVAE, RTVAE, ADS-GAN, PATE-GAN, Bayesian network), TabDDPM and ARF call a column with 10 or fewer distinct values categorical, and its metrics use 5 (`get_frequency`), 10 (DomiasMIA's density model) or 15 (attribute-inference attacks). So nominal codes with more than 10 levels were modelled as numbers, and continuous counts with few values as categories. The fork's `synthcity.utils.dataframe.declared_discrete_columns` context replaces the guess in all of these; `fit_generate`, `build_synthcity_objective`, `run_synthcity_metrics` and the composite HPO objective require the column list. TabPFN's label classifiers get the schema's categorical indices (`categorical_features_indices`) as its unsupervised model already did.

## Column roles

`data.quasi_identifier_columns`, `data.sensitive_columns` and `data.protected_columns` follow statistical disclosure control usage (Hundepool et al., *Statistical Disclosure Control*, 2012; sdcMicro). Quasi-identifiers are public, linkable attributes (age, sex, region); sensitive columns are the secrets an attacker tries to infer (a diagnosis, income); protected columns define fairness groups. Before step 8 one `sensitive_columns` list fed all three roles, so attribute-inference metrics tried to infer sex and age. The config now fails if `sensitive_columns` is set without `protected_columns`, so a config written for the old meaning cannot carry over silently.

| Anonymeter inference | quasi-identifier and sensitive | Infers each sensitive column from the QIs, with the holdout split as the control. This is the only metric that models the declared QI attacker. |
| Anonymeter singling out | none (every column) | |

Two attacker models are in play. synthcity's data_leakage and SynthEval's att_discl assume an attacker who knows every column except the one being inferred, and they have no holdout control, so they cannot separate leakage from a generator that simply learned the population. Anonymeter inference assumes an attacker who knows only the declared quasi-identifiers and compares against the holdout, so it measures leakage beyond generalization. Read the first group as a worst-case screen and Anonymeter as the evidence for the declared threat model. synthcity's k-anonymization and l-diversity are KMeans clustering proxies computed on the synthetic table, not exact equivalence classes over the QIs, and say little about re-identifying real patients. Patching the libraries to accept quasi-identifiers was considered and rejected: Anonymeter already covers that attack with a control, and the patch would be a large fork deviation to maintain.

For each protected group (the fairness metrics' groups, at least 5% of train rows, `data.protected_bins` for numeric columns), the AUC of telling the group's training patients from its test patients by each patient's closest in-group encounter to the synthetic data. All training patients of the group are members (the overall metric subsamples train to the test size; an AUC does not depend on class sizes, and more members lower its variance). Groups with fewer than 10 train or test patients get no AUC. Gap = largest max - min AUC within one protected column (Kulynych et al. measure disparate vulnerability as the difference in membership-attack vulnerability between groups, using an accuracy-based advantage; we use the AUC of the existing distance attack instead, which needs no threshold and has the same 0.5 no-leak value in every group); max = worst group's AUC. Each group's Hanley & McNeil (1982) standard error is in `privacy_subgroups.csv`; the gap is not corrected for the upward bias of a max over noisy groups, so a gap under about two standard errors should be read as noise. Unranked, filed under fairness: a copy of train scores AUC 1 in every group, so its gap is 0, the same as an independent draw (copy-blind); the worst group largely repeats `distance_mia_auc`. Unit tests (`test_privacy_attacks.py::TestSubgroupPrivacy`): copying one group's training rows gives that group AUC 1, the other about 0.5 and a gap above 0.3, while a full copy gives gap 0 and fresh data a worst group near 0.5; the standard error matches the closed form. Not per group: Anonymeter (its evaluators expose no per-target outcomes without private internals). |
